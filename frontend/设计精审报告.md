## 一、视觉一致性

### 1.1 颜色系统

**当前状态**: 有完整的 CSS 变量设计系统（`global.css`），定义了主色 `--accent: #0e6e6a`（工业深青蓝）、点缀色 `--accent-warm: #c2703d`（暖铜橙）、中性色阶、语义色等。整体色彩体系专业且有工业美感。

**问题**:
- **[高] 硬编码颜色残留**：`ChatView.vue` 中发送按钮使用硬编码 `background: linear-gradient(135deg, #13a89e 0%, #0e6e6a 100%)`，应使用 `var(--accent)` 系列。`LoginView.vue` 登录按钮同样硬编码。`GraphView.vue` 时间轴实体标签 `style="color:#333"` 硬编码。
  - **建议**: 统一使用 CSS 变量，新增 `--accent-gradient` 等梯度变量
  - **工作量**: 小

- **[中] Element Plus 主色覆盖不完整**：`global.css` 定义了 `--el-color-primary` 系列，但 `ChatView.vue` 中 `el-radio-button` 的选中态仍可能出现 Element Plus 默认蓝色闪现（样式加载时序问题）
  - **建议**: 确认 `unplugin-auto-import` 的样式注入时序，或在 `global.css` 中用 `!important` 强制覆盖
  - **工作量**: 小

- **[中] 语义色使用不统一**：`DocumentsView.vue` 中向量化状态用 `var(--success, #1c8a5a)`、`var(--danger, #d14e4e)`（带 fallback），而 `global.css` 定义的是 `--color-success`、`--color-danger`。命名不一致，`--success` vs `--color-success`
  - **建议**: 统一语义色变量命名，去除 fallback，确保单一来源
  - **工作量**: 中

### 1.2 间距/圆角/阴影

**当前状态**: 定义了完整的圆角系统（`--radius-xs` 到 `--radius-xl`）、阴影层次（`--shadow-xs` 到 `--shadow-lg`）、8px 格栅间距系统。

**问题**:
- **[中] 间距未完全遵循 8px 格栅**：`ChatView.vue` 消息间距 `margin-bottom: 26px` 不是 8 的倍数；`sidebar-header padding: 18px 20px 16px` 混合了非格栅值。
  - **建议**: 所有间距统一使用 `var(--space-N)` 变量
  - **工作量**: 中

- **[低] 圆角使用有小范围不一致**：`ChatView.vue` 输入框圆角 `16px`（`--radius-xl`），发送按钮 `12px`（`--radius-lg`），消息气泡 `14px`（无对应变量）。建议新增 `--radius-bubble: 14px` 或统一到现有梯度。
  - **建议**: 新增 `--radius-bubble` 变量，或将消息气泡统一为 `--radius-lg`
  - **工作量**: 小

### 1.3 字体/排版

**当前状态**: 定义了 `--font-display`、`--font-body`、`--font-mono` 三族字体。标题使用 `font-display`，数字/代码使用 `font-mono`。

**问题**:
- **[中] 字体大小层次缺少系统化定义**：`global.css` 没有定义 `--text-xs`、`--text-sm`、`--text-base`、`--text-lg` 等字体大小变量。各组件中字体大小散落：`11px`、`12px`、`12.5px`、`13px`、`13.5px`、`14px`、`15px`、`16px`、`18px`、`24px`、`40px`，没有清晰的 scale。
  - **建议**: 定义字体大小梯度变量（如 `--text-xs: 11px`、`--text-sm: 12px`、`--text-base: 14px`、`--text-lg: 16px`、`--text-xl: 18px`、`--text-2xl: 24px`、`--text-3xl: 32px`）
  - **工作量**: 中

- **[低] 行高未统一**：`body` 设 `line-height: 1.6`，消息内容 `1.7`，描述文字 `1.5`，部分组件未设置。建议定义 `--leading-tight: 1.3`、`--leading-normal: 1.6`、`--leading-relaxed: 1.75`。
  - **工作量**: 小

### 1.4 图标风格

**当前状态**: 统一使用 Element Plus Icons，按需注册 22 个图标（`main.js`），风格一致。

**问题**:
- **[低] 部分图标语义不匹配**：`MainLayout.vue` 中「MCP 市场」使用 `Shop` 图标，语义不够直观；「DMS 文档源」使用 `Download` 图标，与实际功能不符。
  - **建议**: 更换为更语义化的图标（如 MCP → `Connection`/`Plug`，DMS → `Files`/`FolderOpened`）
  - **工作量**: 小

## 二、交互细节

### 2.1 Hover/Active/Focus 状态

**当前状态**: `global.css` 定义了 `:focus-visible` 规则，大部分组件有 hover 状态。

**问题**:
- **[高] 侧边栏导航项缺少 focus 状态**：`MainLayout.vue` 的 `.category-item` 使用 `@click` 而非 `<button>` 或 `<a>`，键盘 Tab 无法导航到这些项。虽然 `global.css` 有 `category-item:focus-visible` 规则，但 `<div>` 默认不可聚焦。
  - **建议**: 将导航项改为 `<button>` 或 `<router-link>`，添加 `tabindex="0"` 和 `role="link"`
  - **工作量**: 小

- **[中] 对话列表项缺少 focus 样式**：`ChatView.vue` `.conversation-item` 是 `<div>`，无 `tabindex`，键盘不可达。
  - **建议**: 添加 `tabindex="0"` + `role="button"` + focus 样式
  - **工作量**: 小

- **[中] 知识图谱页面返回按钮 focus 样式缺失**：`PageBack.vue` 已正确实现 `tabindex` 和 `@keydown.enter`，但 hover 时颜色变化 `var(--accent, #4f46e5)` 的 fallback 值（`#4f46e5` 是旧蓝紫色），与当前主题不一致。
  - **建议**: 更新 fallback 值为 `#0e6e6a`
  - **工作量**: 小

### 2.2 加载状态

**当前状态**: `LoadingBlock.vue` 提供了基础的旋转加载图标。`ChatView.vue` 有"思考中..."文字提示。`DocumentsView.vue` 有向量化进度条。

**问题**:
- **[高] 缺少骨架屏（Skeleton）**：文档列表、对话历史列表、图谱数据加载时只有简单的 loading spinner，没有骨架屏。用户会看到空白→内容的跳变，体验不佳。
  - **建议**: 为文档卡片列表、对话列表、图谱面板添加骨架屏组件
  - **工作量**: 大

- **[中] ChatView 加载态过于简单**："思考中..."只有文字，没有动画。建议使用打字机效果的三个点动画（`...` 逐个出现）。
  - **建议**: 添加 CSS 动画的"思考中"指示器
  - **工作量**: 小

### 2.3 空状态

**当前状态**: `EmptyState.vue` 组件提供基础空状态（图标+标题+提示）。`ChatView.vue` 有精心设计的空状态（品牌 logo + 快捷提问 chips）。

**问题**:
- **[中] EmptyState 组件缺少操作按钮**：`EmptyState.vue` 只有文字提示，没有引导用户下一步操作的按钮。例如文档页面空状态提示"上传 PDF、PPT、XLSX 或 DOCX 文件开始使用"，但没有"上传文档"按钮。
  - **建议**: 添加可选的 `action` slot 或 `actionText`/`actionHandler` props
  - **工作量**: 小

- **[低] 图谱空状态位置问题**：`GraphView.vue` 中 `EmptyState` 使用 `class="graph-empty-abs"` 做绝对定位，但 `EmptyState` 组件内部没有 `height: 100%`，可能导致不能完美居中。
  - **建议**: 在 `graph-empty-abs` 类中确保 `display: flex; align-items: center; justify-content: center`
  - **工作量**: 小

### 2.4 错误状态

**当前状态**: `FilePreview.vue` 有错误状态（图标+错误信息）。API 错误通过 `ElMessage.error()` 弹出。

**问题**:
- **[中] 错误信息不够友好**：多处直接显示原始错误信息，如 `'加载会话失败: ' + (e.response?.data?.detail || e.message)`。用户看到 500 Internal Server Error 或 JSON 解析错误会困惑。
  - **建议**: 建立错误码映射表，将技术错误转为用户友好提示（如"网络连接失败，请检查网络"、"服务器繁忙，请稍后重试"）
  - **工作量**: 中

- **[低] 错误信息无统一展示位置**：有些用 `ElMessage.error()`（顶部 toast），有些用内联 `error` 变量（如 `LoginView.vue`），体验不一致。
  - **建议**: 定义错误展示策略：toast 用于操作反馈，内联用于表单验证，全屏用于页面级错误
  - **工作量**: 中

### 2.5 过渡动画

**当前状态**: `global.css` 定义了 `--duration-fast/base/slow`、`fade` 过渡、`stagger-item` 列表渐入。`LoginView.vue` 有精致的 hover 动画。

**问题**:
- **[中] 页面切换缺少过渡**：`MainLayout.vue` 的 `<router-view />` 没有 `<transition>` 包裹，页面切换是硬切。`global.css` 已定义 `.page-fade-*` 类但未使用。
  - **建议**: 用 `<router-view v-slot="{ Component }"><transition name="page-fade"><component :is="Component" /></transition></router-view>` 包裹
  - **工作量**: 小

- **[低] 对话列表切换无过渡**：`ChatView.vue` 切换会话时消息列表直接替换，没有渐入效果。
  - **建议**: 为消息列表添加 `stagger-item` 动画
  - **工作量**: 小

## 三、响应式

### 3.1 布局适配

**当前状态**: `LoginView.vue` 有 `@media (max-width: 860px)` 隐藏品牌区的适配。其他页面没有响应式断点。

**问题**:
- **[高] 主布局无移动端适配**：`MainLayout.vue` 侧边栏固定 `width: 248px`，在平板（768px）和手机（375px）下会挤压主内容区。没有折叠/抽屉式侧边栏的适配方案。
  - **建议**: 添加 `<768px` 断点：侧边栏默认隐藏，通过汉堡菜单抽屉式展开
  - **工作量**: 大

- **[高] ChatView 无移动端适配**：`chat-sidebar` 固定 `width: 240px`，在移动端会占据大部分屏幕。对话列表和对话区没有切换式布局。
  - **建议**: 移动端隐藏侧边栏，通过顶部按钮切换会话列表/对话区
  - **工作量**: 大

- **[高] DocumentsView 无移动端适配**：`docs-sidebar` 固定 `width: 208px`，文档卡片 `grid-template-columns: repeat(auto-fill, minmax(280px, 1fr))` 在窄屏下可能只显示一列但侧边栏仍占据空间。
  - **建议**: 移动端侧边栏折叠为抽屉，卡片最小宽度调整为 200px
  - **工作量**: 大

- **[中] GraphView 图谱在小屏幕上操作困难**：筛选器 `flex-wrap: wrap` 但没有考虑移动端布局，tab 和筛选器会堆叠。
  - **建议**: 移动端将筛选器收入折叠面板
  - **工作量**: 中

### 3.2 文字/内容溢出

**问题**:
- **[中] 长文件名截断处理不一致**：`DocumentsView.vue` 卡片视图 `.doc-card-title` 有 `text-overflow: ellipsis`，但表格视图依赖 `show-overflow-tooltip`（Element Plus 的 title tooltip），两者行为不一致。
  - **建议**: 统一截断策略，tooltip 样式与设计系统一致
  - **工作量**: 小

## 四、可访问性

### 4.1 对比度

**当前状态**: 主色 `#0e6e6a` 在白色背景上对比度约 5.2:1（AA 通过）。文字色阶整体合理。

**问题**:
- **[中] 辅助文字对比度不足**：`--text-tertiary: #8b949e` 在白色背景上对比度约 3.3:1，不满足 WCAG AA 的 4.5:1 要求（普通文本）。大量使用在时间戳、提示文字、标签等场景。
  - **建议**: 将 `--text-tertiary` 调暗至 `#6b7280` 或更深（对比度 ≥ 4.5:1），或将使用 `--text-tertiary` 的文字限制在 ≥ 18px（大文本只需 3:1）
  - **工作量**: 小

- **[低] 用户消息气泡中的白色文字在渐变背景上对比度**：`ChatView.vue` 用户消息使用 `color: #fff` 在 `linear-gradient(135deg, rgba(14,110,106,0.92), rgba(11,79,76,0.92))` 上，对比度约 5.8:1，勉强通过。但渐变末端可能因渲染差异略低。
  - **建议**: 确保渐变最浅处对比度 ≥ 4.5:1
  - **工作量**: 小

### 4.2 键盘导航

**当前状态**: `PageBack.vue` 有完整的键盘支持。`global.css` 有 `:focus-visible` 规则。

**问题**:
- **[高] 侧边栏导航不可键盘访问**：`MainLayout.vue` 导航项是 `<div>` + `@click`，无法通过 Tab 聚焦，无法通过 Enter/Space 激活。
  - **建议**: 改为 `<button>` 或添加 `tabindex="0"` + `role="link"` + `@keydown.enter`
  - **工作量**: 小

- **[中] 对话列表不可键盘访问**：`ChatView.vue` 会话列表项是纯 `<div>` + `@click`。
  - **建议**: 同上处理
  - **工作量**: 小

- **[中] 快捷提问 chips 不可键盘访问**：`ChatView.vue` 空状态的 `.chat-empty-chip` 是 `<span>` + `@click`。
  - **建议**: 改为 `<button>` 添加 `tabindex`
  - **工作量**: 小

### 4.3 屏幕阅读器

**问题**:
- **[中] 消息区域缺少 ARIA 标记**：`ChatView.vue` 消息列表没有 `role="log"` 或 `aria-live="polite"`，屏幕阅读器不会自动播报新消息。
  - **建议**: 为消息容器添加 `role="log"` + `aria-live="polite"` + `aria-label="对话消息"`
  - **工作量**: 小

- **[中] 图谱 canvas 无替代文本**：`GraphView.vue` 的 `<canvas>` 没有 `aria-label` 或 `<canvas>` 内的 fallback 内容，屏幕阅读器用户完全无法获取图谱信息。
  - **建议**: 添加 `aria-label="知识图谱可视化"` 和 `role="img"`
  - **工作量**: 小

- **[低] 图标按钮缺少 aria-label**：`ChatView.vue` 发送按钮有 `title` 但无 `aria-label`。赞/踩按钮有 `title` 但缺少 `aria-pressed` 状态。
  - **建议**: 添加 `aria-label` 和 `aria-pressed`（用于 toggle 按钮）
  - **工作量**: 小

## 五、信息架构

### 5.1 页面标题/导航

**当前状态**: 侧边栏有清晰的导航分组（"工作台"标签）。各页面有工具栏标题。

**问题**:
- **[中] 缺少面包屑导航**：进入文档详情（`DocumentDetail.vue`）后，只有 `PageBack` 组件提供返回，没有显示当前位置的面包屑（如：文档管理 > 连接器选型指南）。
  - **建议**: 在文档详情、图谱等子页面添加面包屑组件
  - **工作量**: 中

- **[低] 页面标题不一致**：`DocumentsView.vue` 工具栏标题是动态的 `activeCategory || '全部文档'`，但 `GraphView.vue` 没有页面标题（只有 tab 切换），`ConfigView.vue` 等未知。
  - **建议**: 统一使用 `page-header` 组件（`global.css` 已定义），确保每个页面有标题+描述
  - **工作量**: 中

### 5.2 操作反馈

**当前状态**: 大部分操作有 `ElMessage.success/error` 反馈。

**问题**:
- **[中] 删除操作确认弹窗样式不统一**：`DocumentsView.vue` 使用 `ElMessageBox.confirm` 自定义文案，`ChatView.vue` 使用默认文案。确认按钮颜色/文案不统一。
  - **建议**: 封装统一的确认弹窗工具函数，统一危险操作的确认流程
  - **工作量**: 小

- **[低] 上传成功后缺少明确的状态切换**：`DocumentsView.vue` 上传成功后显示向量化进度条，但没有明确的"上传完成→向量化中→完成"的状态机视觉反馈。
  - **建议**: 使用步骤条或状态标签明确展示流程阶段
  - **工作量**: 中

### 5.3 表单验证

**当前状态**: `LoginView.vue` 有 `el-form` + `rules` 验证。

**问题**:
- **[中] 新建文件夹弹窗无验证**：`DocumentsView.vue` 新建文件夹对话框的输入框没有 `rules`，空值提交时只靠 `ElMessage.warning` 提示，输入框本身没有错误态。
  - **建议**: 添加 `el-form` + `rules` 或至少输入框 `:error` 状态
  - **工作量**: 小

- **[低] 登录表单验证触发时机**：`rules` 设为 `trigger: 'blur'`，但提交时如果用户直接点登录（未 blur），可能跳过验证。
  - **建议**: `handleSubmit` 中先调用 `formRef.value.validate()` 再提交
  - **工作量**: 小

## 六、细节打磨

### 6.1 按钮尺寸/间距

**问题**:
- **[中] 侧边栏导航项 padding 过小**：`.category-item` padding `9px 14px`，在高 DPI 屏幕上点击区域偏小（约 36px 高度），不符合移动端 44px 最小触摸目标。
  - **建议**: 将 padding 增加到 `10px 14px`，确保高度 ≥ 40px
  - **工作量**: 小

- **[低] 工具栏按钮间距不一致**：`DocumentsView.vue` 工具栏 `gap: 12px`，但 `GraphView.vue` tabs 区 `gap: 16px`。
  - **建议**: 统一工具栏/操作区按钮间距为 `var(--space-3)` (12px)
  - **工作量**: 小

### 6.2 表格/列表可读性

**问题**:
- **[中] 表格行高偏紧**：Element Plus 默认行高较小，在展示文件名+标签的复合内容时略拥挤。
  - **建议**: 覆盖 `--el-table-row-height` 为 `48px` 或更大
  - **工作量**: 小

- **[低] 文档卡片信息密度过高**：卡片内显示文件名、块数、大小、更新时间、分类标签、型号标签、材料标签，信息过多。
  - **建议**: 减少默认展示的标签数量（型号/材料各展示 2 个），其余折叠
  - **工作量**: 小

### 6.3 弹窗/抽屉

**当前状态**: 使用 Element Plus 的 `el-dialog` 和 `el-drawer`，`global.css` 做了圆角覆盖。

**问题**:
- **[中] 弹窗宽度未使用响应式值**：多处弹窗使用固定宽度（`width="360px"`、`width="460px"`、`size="420px"`），在小屏幕上可能溢出。
  - **建议**: 使用 `min-width` + `max-width: 90vw` 组合，或使用百分比宽度
  - **工作量**: 小

- **[低] FilePreview 弹窗过大**：`width="85%"` + `top="3vh"`，在大屏幕上内容区非常大，但文档预览内容（如 Word）可能不占满。
  - **建议**: 根据文件类型调整弹窗大小，或使用全屏预览模式
  - **工作量**: 中

### 6.4 文字截断/换行

**问题**:
- **[中] 代码块在消息气泡中可能溢出**：`ChatView.vue` 使用 `v-html` 渲染 Markdown，但 `.message-content` 没有 `overflow-x: auto` 处理，长代码行可能撑破气泡。
  - **建议**: 添加 `pre, code { overflow-x: auto; max-width: 100%; }` 到消息内容样式
  - **工作量**: 小

- **[低] 图谱节点名称截断不一致**：`GraphView.vue` canvas 中节点名截断到 10 字符加 `…`，但 drawer 中的实体名不截断，可能很长。
  - **建议**: drawer 中实体名添加 `text-overflow: ellipsis`
  - **工作量**: 小
