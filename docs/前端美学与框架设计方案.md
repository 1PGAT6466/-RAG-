# 伏羲 RAG · 前端美学与框架设计方案

> 版本：v1.0（2026-08-28）
> 范围：设计系统、组件架构、视觉质感、响应式、可访问性、性能
> 基线：现有设计系统已达 v2（参 easyclaw / mimo / obsidian / workbuddy），tokens 完善，六页均已实现
> 结论：**不重建 tokens，聚焦「逐页落实 + 架构治理 + 工程化升级」**

## 〇、现状评估（先校准，避免过度设计）

### 已经做得好的（不动）

| 维度 | 现状 | 评价 |
|------|------|------|
| 设计 tokens | `global.css` 已定义完整中性色阶 / 主色渐变 / 文字层级 / 圆角 / 阴影 6 档 | ✅ 成熟 |
| Element Plus 精致化 | `--el-color-primary` 映射、按钮/输入/表格/弹窗圆角阴影全覆盖 | ✅ 到位 |
| 页面骨架 | 侧边栏 pill 导航、登录卡片、上传区、空状态、doc-card、图谱 hover 高亮 | ✅ 已精细 |
| 页面过渡 | `page-fade` 路由切换淡入 | ✅ 有 |
| 暗色预留 | tokens 用 `var(--)` 集中管理，可平滑切暗色 | ✅ 架构好 |

### 真实的短板（本次要解决）

1. **响应式缺失**：`app-layout` 固定 248px 侧边栏 + `#app { height:100vh; overflow:hidden }`，窄屏/移动端直接挤压或溢出，无 `@media` 断点。
2. **可访问性（a11y）为零**：无 `:focus-visible` 焦点环、无 `prefers-reduced-motion` 降级、键盘导航未显式保障（图谱全靠鼠标 hover）。
3. **组件复用不充分**：`SchemaForm.vue` / `SchemaResult.vue` 之外，各 view 里大量重复的内联样式和弹窗逻辑（尤其是 DocumentsView / GraphView 的工具栏、空状态、loading 三件套）。
4. **性能未优化**：`main.js` 全量注册 250+ Element Plus 图标组件（`for...of` 全局注册），首屏包体积偏大；D3 力导向图无节流，大量节点时卡顿。
5. **配置未显式管理**：`vue.config` 无 Vite 路径别名、无 `manualChunks` 分包、无构建产物分析。

## 一、设计系统层（P0，立竿见影）

### 1.1 补齐交互态 tokens（当前只有常态色）

```css
:root {
  /* 焦点环（可访问性核心） */
  --focus-ring: 0 0 0 3px var(--accent-glow);
  --focus-ring-color: var(--accent);

  /* 语义色（当前散落在 tag 里硬编码） */
  --color-success: #22a05a;
  --color-warning: #e6a23c;
  --color-danger:  #f56c6c;
  --color-info:    #909399;

  /* 动效时长（当前散落 0.15s/0.18s/0.2s 各写各的） */
  --duration-fast: 0.12s;
  --duration-base: 0.18s;
  --duration-slow: 0.28s;
  --ease-out: cubic-bezier(0.2, 0, 0, 1);
  --ease-in-out: cubic-bezier(0.4, 0, 0.2, 1);
}
```

**收益**：语义色从硬编码收敛到 token，便于未来切暗色主题；动效时长统一，消除「每个页面节奏不一」的生硬感。

### 1.2 统一焦点可见性（a11y）

```css
:focus-visible {
  outline: none;
  box-shadow: var(--focus-ring);
}
.category-item:focus-visible,
.doc-card:focus-visible,
.el-button:focus-visible {
  outline: 2px solid var(--focus-ring-color);
  outline-offset: 2px;
}
```

### 1.3 动效降级（a11y + 性能）

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.001ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.001ms !important;
  }
}
```

## 二、响应式布局层（P0，当前最痛）

### 2.1 侧边栏断点策略

```css
/* ≥1200px：完整侧边栏 */
@media (max-width: 1200px) {
  :root { --sidebar-width: 208px; }
}

/* <960px：侧边栏可折叠为图标栏 */
@media (max-width: 960px) {
  .sidebar { width: 64px; min-width: 64px; }
  .sidebar-title, .sidebar-sub, .nav-group-label,
  .category-item span:not(.el-icon), .user-badge span:not(.user-avatar) { display: none; }
  .category-item { justify-content: center; padding: 12px 0; }
}

/* <640px：移动端——侧边栏变成顶部抽屉 */
@media (max-width: 640px) {
  .app-layout { flex-direction: column; }
  .sidebar { width: 100%; min-width: 100%; height: auto; }
  .main-content { min-height: 0; }
  .doc-list { grid-template-columns: 1fr; }
  .chat-container { max-width: 100%; }
  .message-content { max-width: 88%; }
}
```

**收益**：一顿断点，从「只在桌面能用」变成「平板/手机可浏览」，这是内网浏览器作为数据门户的刚需（用户问题 3 的核心）。

### 2.2 移动端侧边栏交互

- 侧边栏折叠开关（顶部汉堡按钮 + `transition width 0.2s`）。
- 用 `localStorage` 记忆折叠态，刷新不丢失。

## 四、性能层（P1，工程化）

### 4.1 图标按需引入（首屏体积 -60% 以上）

当前 `main.js` 全量 `for...of` 注册所有 Element Plus 图标。改为显式导入仅用到的图标：

```js
// main.js
import { ChatDotRound, Folder, Connection, Grid, Shop, Setting, SwitchButton } from '@element-plus/icons-vue'
for (const [name, comp] of Object.entries({ ChatDotRound, Folder, Connection, Grid, Shop, Setting, SwitchButton })) {
  app.component(name, comp)
}
```

**收益**：Element Plus 图标全量约 250+ 个组件，白名单引入后打包体积显著下降，首屏更快。

### 4.2 Vite 构建优化（vite.config.js）

```js
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import path from 'path'

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: { '@': path.resolve(__dirname, 'src') }
  },
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          'vue-vendor': ['vue', 'vue-router', 'pinia'],
          'element-plus': ['element-plus'],
          'd3': ['d3'],
        }
      }
    },
    chunkSizeWarningLimit: 800,
  },
  server: {
    port: 3000,
    proxy: { '/api': 'http://127.0.0.1:8099' }
  }
})
```

**收益**：`@` 别名消除 `../../` 深路径；`manualChunks` 让 element-plus/d3 成为独立缓存 chunk，改业务代码不失效 vendor 缓存；`proxy` 配置进仓库（当前散在命令行）。

### 4.3 D3 力导向图节流

`GraphView.vue` 的力模拟 tick 事件加 `requestAnimationFrame` + 节点数阈值（>500 节点降采样或关闭 label 计算），避免大量节点时主线程卡死。

## 五、可访问性层（P2，内网场景的合规与体验）

1. **键盘导航**：文档卡片、导航项加 `tabindex="0"` + `@keyup.enter` 触发点击。
2. **语义化**：`<aside>`/`<main>`/`<nav>` 已正确，补充 aria-label。
3. **对比度**：`--text-tertiary #9aa1ad` 在 `--bg-secondary #f7f8fa` 上的对比度约 2.5:1，低于 WCAG AA（4.5:1）——仅用于装饰性文字可，但功能性说明文字应提升到 `--text-secondary #5f6672`。
4. **图表的文字替代**：知识图谱作为纯 SVG 对屏幕阅读器不可达，需提供数据表格作为语义等价物（可折叠面板）。

**说明**：内网系统，a11y 非刚需，但「浏览器门户」长期有人高频使用，键盘操作 + 对比度是性价比最高的体验投资。

## 六、视觉质感微调（P2，锦上添花，非必须）

在 token 已完善基础上，仅做「克制」的质感提升，避免过度设计：

1. **登录页**：已用渐变背景，可加一个淡入的品牌 Logo 动效（`@keyframes` 上浮 0.6s）。
2. **空状态插画**：当前是半透明图标，可加柔和的几何装饰（纯 CSS 渐变圆，不引第三方图）。
3. **加载骨架屏**：文档列表/详情加载用 `el-skeleton` 替代 `v-loading`，首屏体验更稳。
4. **微交互动效**：卡片 hover 已 `translateY(-2px)`，可统一加 `transition: transform var(--duration-base) var(--ease-out)`。

## 九、需你确认的决策点

1. **响应式深度**：是否要真移动端（顶部抽屉侧边栏），还是仅「平板可用」就够？内网多在大屏访问，移动端可能过度投入。
2. **图标按需引入**：需梳理当前实际用到的图标清单（约 20-30 个），是否可以接受我在改动时顺带统计？
3. **D3 图谱性能**：当前节点规模（42 文件节点 + 关系）是否已感卡顿？若未卡顿，4.3 可暂缓。
4. **a11y 投入**：内网系统是否需要在 WCAG 基础上投入，还是「键盘可用 + 焦点环」即可？
